## Summary

修复移动端页面背景出现“断层/分块”的问题：将背景从 `body` 的普通背景改为一个固定铺满视口的渐变背景层（`body::before`），并补充一条自然的纵向渐变过渡，保证页面滚动多长都不会出现背景高度不足或分段渲染的明显拼接线。

## Current State Analysis

- 当前背景定义在 `body { background: radial-gradient(...), ... , var(--bg); }`，见 [styles.css](file:///d:/Github_Try/xiaohan/adhd-demo/styles.css#L27-L36)。
- `html, body { height: 100%; }` 见 [styles.css](file:///d:/Github_Try/xiaohan/adhd-demo/styles.css#L21-L25)。在部分移动端浏览器/内置 WebView/PWA 的合成渲染里，长页面滚动时可能出现背景在不同合成层/分块渲染，导致可见的横向拼接线（你截图里的“断层”）。

## Proposed Changes

### 1) 改成固定背景层（解决“背景不够长/分块拼接”）

修改 [styles.css](file:///d:/Github_Try/xiaohan/adhd-demo/styles.css)：

- 将现有 `body` 的多层 radial 背景迁移到 `body::before`（或 `body::after`）：
  - `position: fixed; inset: 0;` 保证始终覆盖整个视口，不依赖页面高度。
  - `pointer-events: none;` 避免遮挡交互。
  - `z-index: -1;` 并配合 `body { position: relative; }`、`.app { position: relative; z-index: 0/1; }`，确保背景在最底层。
- `html`/`body` 补一个纯色兜底背景（`background: var(--bg);`），避免极端情况下伪元素层未渲染时出现闪白。

### 2) 加一条自然的纵向渐变（更“连续”、减少色块感）

同样在 `body::before` 的 `background` 最底层新增一个纵向 `linear-gradient`，作为主过渡底色，例如：

- `linear-gradient(180deg, #fff7fb 0%, #fff1f8 45%, #f6d6ea 100%)`

并保留原有 2~3 个 radial “彩色光斑”层叠在上面（适度降低 alpha），让整体从上到下更自然，不会出现“上面白、下面突然粉”的分割感。

### 3) 调整根元素高度声明（减少移动端渲染异常概率）

将 `html, body { height: 100%; }` 调整为更稳妥的写法：

- `min-height: 100%;` 或删除 `height: 100%`，改由布局容器 `.app { min-height: 100vh; }` 保证撑高。

目的是减少某些 UA 对 `height: 100%` + 长页面滚动时的背景传播/合成异常。

### 4) 缓存版本更新（移动端 PWA/缓存可见）

由于该项目启用了 Service Worker 缓存（见 [sw.js](file:///d:/Github_Try/xiaohan/adhd-demo/sw.js)），需要同步更新：

- `index.html` 中的 `styles.css?v=...` 版本号
- `sw.js` 中的 `CACHE_NAME` 与 `ASSETS` 列表

确保手机端不会一直加载旧的样式资源，从而误判“没修好”。

## Assumptions & Decisions

- 不更换整体配色体系，沿用现有 `--bg / --pink / --sky / --mint` 的色相，仅通过新增纵向渐变与固定背景层解决断层。
- 背景层使用纯 CSS（不引入图片资源），保持离线版可用与体积最小化。

## Verification Steps

- 桌面浏览器：滚动页面到最底部，观察背景是否全程连续，无横向拼接线。
- 移动端 Safari/Chrome（含“添加到主屏幕后”的 PWA 模式）：
  - 上下滚动多次、快速滑动、触发地址栏收起/展开，观察是否仍有断层。
  - 若仍出现断层：调低 radial 光斑透明度、减少光斑层数，并检查是否有 `backdrop-filter` 造成的合成层分割（必要时对背景层加 `transform: translateZ(0)` 强制合成一致性）。
